# ホームページ更新マニュアル

このマニュアルは、**プログラミングの知識がなくてもサイトを更新できる**ように
手順をまとめたものです。パソコンへのソフトのインストールは不要で、
ブラウザ（ChromeやEdge）だけで作業できます。

---

## いちばん大事なこと

このサイトは、**公開前に必ず見た目を確認できる仕組み**になっています。

```
編集する  →  確認用のURLが自動で作られる  →  見た目をチェック  →  OKなら公開
```

確認せずにいきなり本番が変わることはありません。**途中でやめることもできます。**
間違えても元に戻せるので、安心して進めてください。

> **ひとつだけ守ってください**
> 後述の手順にある「**Create a new branch**（新しいブランチを作る）」を必ず選ぶこと。
> これを選ばないと、確認なしで本番サイトが変わってしまいます。

---

## 1. お知らせを追加する

### 手順①　ファイルを開く

1. ブラウザで https://github.com/Tsubasa-Kato-2/ishiyama-kensetsu-web を開く
2. 画面上部の検索窓の下あたりにあるファイル一覧から、`src` → `lib` → `news.ts` と進む
3. 右上の**鉛筆マーク（✏️）**をクリック（マウスを乗せると "Edit this file" と出ます）

### 手順②　記事を書き足す

`export const newsList: NewsItem[] = [` という行を探してください。
**その次の行**に、以下をまるごと貼り付けます。

```
  {
    slug: "news-20261015",
    date: "2026.10.15",
    tag: "お知らせ",
    title: "ここにタイトルを書く",
    body: `ここに本文の1段落目を書きます。

空行を1つ入れると、段落が変わります。`,
  },
```

**書き換えるのは次の5か所だけです。**

| 項目 | 書き方 | 例 |
|---|---|---|
| `slug` | **半角の英字・数字・ハイフンのみ**。日本語は使えません。他の記事と重複しないように | `news-20261015` |
| `date` | 点（`.`）区切り。月日は必ず2桁 | `2026.10.15` |
| `tag` | `お知らせ` と書くのが基本。`見学会` と書くとラベルがオレンジ色になります | `お知らせ` |
| `title` | 一覧に出る見出し | `秋の見学会を開催します` |
| `body` | 本文。**前後の記号（\`）は消さないこと** | |

> **`slug` に困ったら**、日付をそのまま使って `news-20261015` のようにすれば確実です。

### 手順③　確認用のページを作る

1. 右上の緑のボタン **「Commit changes...」** をクリック
2. 小さな入力欄が出るので、1行目に何をしたか書く（例：`お知らせを追加`）
3. **ここが重要です。** 下にある選択肢のうち、
   **「Create a new branch for this commit and start a pull request」**（下側）を選ぶ
4. 緑のボタン **「Propose changes」** をクリック
5. 次の画面で、緑のボタン **「Create pull request」** をクリック

### 手順④　見た目をチェックする

1分ほど待つと、画面の下のほうに自動でメッセージが表示されます。

- **緑のチェックマーク（✓）が出た場合** → 成功です。メッセージ内の
  **「Visit Preview」** または `...vercel.app` で終わるURLをクリックすると、
  **公開前の状態のサイト**が開きます。トップページで新着情報を確認してください。

- **赤いバツ（✗）が出た場合** → 書き方のどこかが間違っています。
  **この時点では本番サイトに一切影響していません。** 下の「うまくいかないとき」を見てください。

### 手順⑤　公開する

プレビューを見て問題なければ、
緑のボタン **「Merge pull request」** → **「Confirm merge」** をクリック。

**これで公開完了です。** 2〜3分で本番サイトに反映されます。

## 2. イベント・見学会を追加する

ファイルが `src/lib/events.ts` になるだけで、**手順①〜⑤はお知らせと全く同じ**です。

`export const upcomingEvents: EventItem[] = [` の次の行に貼り付けます。

```
  {
    id: 2,
    slug: "event-20261101",
    type: "見学会",
    title: "ここにイベント名",
    date: "2026年11月1日（土）・2日（日）",
    time: "10:00〜17:00",
    place: "〒093-0000 北海道網走市○○",
    capacity: "予約制",
    desc: "一覧に表示される短い説明文。",
    tags: ["フルリフォーム", "造作家具"],
    body: "詳細ページの本文。\n\n空行で段落が変わります。",
    eventDates: ["2026-11-01", "2026-11-02"],
  },
```

**注意する点が3つあります。**

- `id` は**他のイベントと重複しない数字**にしてください（既にある最大の数字＋1でOK）
- `eventDates` は**カレンダー表示用**で、`2026-11-01` のように**ハイフン区切り**です。
  `date` の書き方（`2026年11月1日`）とは別物なので注意してください
- 終了したイベントは、`title` の先頭に `【終了】` を付けます

## 3. 写真を追加する

### 手順①　写真を軽くする（必ず行ってください）

**撮影したままの写真をそのまま上げないでください。** サイトが非常に重くなります。

1. https://squoosh.app/ をブラウザで開く
2. 写真をドラッグ&ドロップ
3. 画面右側の設定で
   - 形式を **MozJPEG** にする
   - **Quality** を **82** にする
   - **Resize** にチェックを入れ、長いほうの辺を **1920** にする
4. 右下のダウンロードボタンで保存

保存したファイルが**500KB以下**になっていればOKです。

### 手順②　アップロードする

1. GitHubで `public` → `images` → 入れたいフォルダ（施工事例なら `works`）を開く
2. 右上の **「Add file」** → **「Upload files」**
3. 写真をドラッグ&ドロップ
4. あとは**お知らせの手順③〜⑤と同じ**（新しいブランチを作ってプレビュー確認）

### ファイル名のつけかた

施工事例の写真は、ルールに沿った名前にしてください。

```
<事例のslug>-01-exterior.jpg     メイン写真（外観）
<事例のslug>-02.jpg, -03.jpg …   完成後の写真（連番）
<事例のslug>-before-01.jpg …     リフォーム前の写真（連番）
```

## 4. うまくいかないとき

### 赤いバツ（✗）が出た

**本番サイトには影響していないので、慌てなくて大丈夫です。** よくある原因は4つです。

| よくある原因 | 直し方 |
|---|---|
| 最後の `,`（カンマ）を消してしまった | `},` の形になっているか確認 |
| `slug` に日本語を使った | 半角英数字に直す |
| 本文の前後の記号（\`）を消した | お知らせの `body` は \` で囲む |
| かっこ `{` `}` の数が合っていない | 貼り付けた範囲を見直す |

直すときは、プルリクエスト画面の **「Files changed」** タブ →
鉛筆マークで再度編集できます。保存すると自動で再チェックされます。

### 全部やり直したい

プルリクエスト画面をいちばん下までスクロールし、
**「Close pull request」** をクリックすれば、なかったことになります。
本番サイトは一切変わりません。

### 公開した後で間違いに気づいた

**自分で直さず、まず管理者に連絡してください。** 公開済みの内容を戻す作業は
手順が異なります。

---

## 5. 触ってはいけないもの

以下は**絶対に編集・削除しないでください**。サイトが表示されなくなります。

- `package.json` / `package-lock.json`
- `next.config.ts` / `tsconfig.json` / `postcss.config.mjs`
- `src/components/` フォルダの中身
- `src/app/` の中の `layout.tsx` や `globals.css`

**更新してよいのは、このマニュアルに書かれているファイルだけ**と考えてください。
